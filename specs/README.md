# 스펙 주도 개발 (SDD)

이 저장소는 **스펙을 먼저 쓰고, 스펙대로 만든다.** 코드는 스펙을 구현한 결과이고, 무엇을·왜 만드는지는 스펙이 기준이다.
사람(GM 사용자)이든 AI 에이전트든 같은 순서를 따른다.

## 문서 지도

| 문서 | 내용 | 언제 읽나 |
| --- | --- | --- |
| [constitution.md](constitution.md) | 바뀌지 않는 원칙 (UI 규칙, 성능, 데이터, 라이선스) | 모든 작업 전에 |
| [architecture.md](architecture.md) | 지금 시스템의 구조·데이터 모델·저장 위치 | 계획(plan)을 쓸 때 |
| `NNN-기능이름/spec.md` | 기능 하나의 요구사항·수용 기준·결정 기록 | 그 기능을 고칠 때 |
| `NNN-기능이름/plan.md` | 어떻게 만들지 (구조·파일·데이터 변경) | 구현 전에 |
| `NNN-기능이름/tasks.md` | 순서 있는 작업 목록과 검증 방법 | 구현하면서 |
| [templates/](templates/) | 위 세 문서의 빈 양식 | 새 기능을 시작할 때 |

## 흐름

```
① 명세 (spec.md)  →  [사용자 확인]  →  ② 계획 (plan.md)  →  ③ 작업 (tasks.md)  →  ④ 구현  →  ⑤ 검증  →  ⑥ 스펙 갱신
```

1. **명세 — 무엇을, 왜.** 사용자의 요청을 `spec.md`로 옮긴다. 구현 방법은 쓰지 않는다.
   사용자 시나리오, 기능 요구사항(FR), 수용 기준(AC), 범위 밖, 열린 질문을 적는다.
   모호한 점은 추측하지 말고 「열린 질문」에 적어 사용자에게 묻는다.
2. **사용자 확인.** 열린 질문이 없고 사용자가 스펙에 동의해야 다음 단계로 간다. (작은 수정은 아래 「작은 변경」 참고)
3. **계획 — 어떻게.** [architecture.md](architecture.md)를 보고 `plan.md`를 쓴다. 바꿀 파일, 데이터 모델·세이브 형식 변경, 이전 세이브 호환, 헌법 점검을 적는다.
4. **작업.** `tasks.md`에 작은 단위로 순서를 정한다. 각 작업에 어떤 FR/AC를 만족시키는지, 어떻게 확인하는지 적는다.
5. **구현.** 작업 순서대로 만든다. 스펙과 다르게 만들어야 할 이유가 생기면 코드보다 **스펙을 먼저** 고치고 사용자에게 알린다.
6. **검증.** 수용 기준을 하나씩 확인한다. 최소한 `npm run check`, Rust를 건드렸으면 `cargo test`·`cargo clippy`, 화면은 실제로 띄워서 본다.
7. **스펙 갱신.** 상태를 `구현됨`으로 바꾸고, 구현하면서 정한 것을 「결정 기록」에 남긴다. [architecture.md](architecture.md)와 README의 기능 설명도 맞춘다.

### 이미 있는 기능을 바꿀 때

새 폴더를 만들지 않고 그 기능의 `spec.md`를 고친다. 바뀐 요구사항은 FR을 고치거나 새 번호를 붙이고,
없앤 요구사항은 지우지 말고 「결정 기록」에 무엇을 왜 없앴는지 남긴다. (예: 「검증(확인) 기능 삭제」)

### 작은 변경

글자·색·간격 조정, 명백한 버그 수정처럼 요구사항이 바뀌지 않는 일은 plan/tasks 없이 고쳐도 된다.
다만 사용자가 정한 규칙이 바뀌는 일(예: 「Enter로 메모 저장」)은 작아도 해당 `spec.md`에 반영한다.

## 규칙

- **폴더 이름**: `specs/NNN-영문-케밥/` (번호는 세 자리, 다음 빈 번호). 문서 내용은 한국어.
- **번호 붙이기**: 기능 요구사항 `FR-001`, 수용 기준 `AC-001`, 비기능 요구사항 `NFR-001`. 번호는 지운 뒤에도 다시 쓰지 않는다.
- **상태**: `초안` → `확정` → `구현 중` → `구현됨` (그만둔 것은 `보류`·`폐기`).
- **헌법이 우선한다.** 스펙이 [constitution.md](constitution.md)와 부딪히면 스펙을 고치거나, 사용자 동의를 받아 헌법을 고친다.
- 사용자가 TASK 번호(예: TASK 1)로 일을 주면 스펙 머리말의 「관련 TASK」에 적는다.
