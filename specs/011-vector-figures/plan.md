# 011 · 벡터로 그린 그림 추출 — 계획

- **스펙**: [spec.md](spec.md)
- **상태**: 확정

## 요약

pdf.js 5의 `constructPath` 연산자는 칠한 경로마다 사용자 좌표의 경계 상자(minMax)를 함께 준다.
이미 그림 영역을 찾느라 훑던 연산자 목록에서 이 상자를 같이 모아(추가 순회 없음), 서로 닿는 상자를 무리로 묶는다.
무리가 **경로 8개 이상**이고 안의 글자 수가 **경로 수 × 2 이하**이면 그림으로 본다.
배치도는 경로 42~76개에 글자 6~16자, 표는 경로 14~29개에 글자 450자 이상이라 이 기준으로 깔끔하게 갈린다.
그림 영역 안에 가운데가 들어가는 줄은 문장 줄에서 뺀다.
직접 자르기는 원본 보기 도구 막대의 토글 하나와 쪽 위 끌기 사각형으로 만들고, 잘라낸 그림은 지금 그림과 같은 `crop` 기록으로 세이브에 남긴다.

## 헌법 점검

## 데이터 모델·세이브 형식

- 타입 변경: 없음. 직접 자른 그림의 id는 `cut-n` (자동 추출의 `img-n`과 겹치지 않게).
- 세이브 키 변경: 없음. `crops`에 `[쪽, x, y, w, h]`로 같이 들어간다.
- 예전 세이브: 그대로 열린다.

## 대안과 고른 이유

- 쪽을 그려서 픽셀로 그림 영역 찾기 → 쪽마다 렌더링이 필요해 느리다.
- 경로 수만으로 판정 → 표(경로 29개)도 그림이 된다. 글자 밀도를 같이 본다.
- 구글 문서 보기에서도 자르기 허용 → 세이브를 다시 열 때 자를 PDF가 없어 그림이 사라진다. 숨김.

## 위험

- 선으로 그린 장식(쪽 테두리·구분선 여러 개)이 그림으로 잡힐 수 있다 → 안에 본문이 있으면 글자 기준에서 걸러진다. 잘못 잡힌 그림은 지우면 된다.
- 마스크 그림 여러 개(`Group`/`Repeat`)는 글꼴 조각일 수 있어 넣지 않았다. 하나짜리 마스크만 그림으로 본다.

## 검증 계획

- 자동: `npm run check`.
- Node 스크립트로 실제 PDF 전체 쪽의 `findFigures` 결과와 처리 시간 비교 (예전 코드와 나란히).
- 화면 (WebKit, 라이트·다크): PDF를 넣고 그림 블록·라벨 줄·표 쪽 문장 확인 → 원본 보기에서 자르기 → 현재 줄 뒤 그림, 세이브의 `crops`, 집합 되돌리기.
- AC-001 ↔ 그림 블록의 쪽, 라벨 줄 없음 / AC-002 ↔ 54쪽 문장 수 / AC-003 ↔ 처리 시간 비교.
